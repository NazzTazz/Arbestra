# Étiquettes GitHub proposées

Proposition à créer sur le dépôt (Issues, puis Labels). Les couleurs sont données sans `#`, telles que GitHub les demande. Les modèles d'issue appliquent déjà `bug`, `gameplay` et `à trancher par Tristan` quand ils sont utilisés (voir [`.github/ISSUE_TEMPLATE`](../.github/ISSUE_TEMPLATE/config.yml)) : crée ces étiquettes en premier, sinon GitHub ignore l'étiquette demandée par le modèle.

| Nom | Couleur | Description |
|---|---|---|
| `bug` | `d73a4a` | Quelque chose ne marche pas comme prévu. |
| `gameplay` | `a371f7` | Touche aux règles ou à l'expérience de jeu : Tristan tranche. |
| `à trancher par Tristan` | `fbca04` | Attend une décision du product owner avant tout développement. |
| `perf` | `ff7b00` | Fluidité, temps de chargement, budgets de performance. |
| `mobile` | `0e8a16` | Téléphones et tablettes : rendu, tactile, orientation. |
| `docs` | `0075ca` | Documentation, guides, specs. |
| `bon premier ticket` | `7057ff` | Tâche bornée, bien décrite, adaptée à une première contribution. |
| `aide bienvenue` | `008672` | Tristan accepte volontiers un coup de main sur ce sujet. |
| `security` | `b60205` | Suivi public d'un correctif de sécurité déjà traité ; les failles se signalent en privé (voir [SECURITY.md](../SECURITY.md)). |

`security` sert au suivi public, après correctif ; le signalement d'une faille passe par le canal privé de GitHub ([SECURITY.md](../SECURITY.md)).
